# PrismLaunch 比赛演示讲稿

适用版本：在 `b47b061` 基础上完成的比赛展示优化版。全程只展示已经实现的功能，不把 Mock 说成真实 AI。

## 开场前准备

1. 启动项目，浏览器打开 `http://localhost:5173`。桌面建议 1920×1080 或 1440×900，浏览器缩放保持 100%，切中文。
2. 从 Materials 下载 `haitao-supplier-demo.xlsx`，放到容易找到的位置。CSV 也可作为备用。
3. 点一次“重置演示”。需要导入时再选择文件，导入后不要马上重置，否则会恢复内置目录。
4. 记住三个商品：主角 `LM-KT-BTL-001-BLK-500`；导入缺重量商品 `LM-KT-IMP-005-BLK-500`；内置缺重量商品 `LM-KT-BTL-005-BLK-500`。
5. 预览和校验都在本地浏览器进行，正式点击“导入 7 个商品”才更换目录。不要声称样例来自真实客户；它是用于验证真实文件解析的演示样例。

## A. 3 分钟版本

主讲顺序为“资料输入 → 修复缺事实 → 选品 → 证据与权限 → 风险审核 → 模拟发布”。先走补重量支线，再走主角主线，最后停在发布成功。

| 时间 | 点击动作 | 建议讲述 |
| --- | --- | --- |
| 0:00–0:15 | 展示 Materials | “供应商资料不一定完整，也不一定足以支持商品宣称。直接翻译成英文 Listing，会把缺资料和无依据的描述一起带到下游。” |
| 0:15–0:35 | 导入供应商文件 → 选样例 → 导入 7 个商品 | “文件在本地真实解析。8 行中有 6 行齐全、1 行缺重量、1 行重复。重复行被跳过，缺资料商品保留供人工补齐。” |
| 0:35–1:05 | 打开导入缺重量商品 → 核对事实 → 包装重量补 `0.42` → 保存 → 确认 | “缺包装重量时不能定价。保存后仍待确认；人工确认后，来源、状态和定价一起变化。这里变成 18.90 美元，来源是当前商品成本加演示费用假设。” |
| 1:05–1:30 | 左侧“上新任务” → 看需求和 Top 3 → 选主角 | “我们按黑色、约 16 盎司、无吸管等条件选品，并解释扣分原因。这是固定演示评分，94 分不是模型置信度。” |
| 1:30–1:50 | 分析证据 → 核对事实 | “V1 保留基础事实，V2 加入任务相关字段。文件行值是真实解析、可以追到行号；V2 新增字段标注为模拟分析的演示样例，没有解析过任何文件。已确认不等于都能写文案，例如重量仍只供内部定价。” |
| 1:50–2:10 | 继续前往文案工作室 → 生成 Amazon 文案 → 展开事实来源 | “正常模板只用已确认且允许使用的字段。为了演示审核，首次草稿故意注入了 100% leakproof，不是正常事实授权产生的内容。” |
| 2:10–2:40 | 继续前往审核 → 运行审核 → 应用建议修订 → 停顿 → 再运行审核 | “没有证据支持绝对防漏，因此红色区域明确拦截发布。修订后是黄色‘需要审核’，不会直接变成通过。必须重新审核当前版本。” |
| 2:40–3:00 | 审核通过 → 发布 → 导出 Amazon CSV | “通过之后才开放模拟发布，CSV 可以真实下载。今天展示的是有来源、有人工决策、有阻断规则的上新流程，没有向真实平台上架。” |

操作提醒：从缺资料详情进入 Fact Review 时，系统已建立固定演示任务，因此之后直接点左侧“上新任务”，不用重新找“创建演示任务”。补齐后的商品也可能达到 94 分；主角在同分时按固定演示规则优先，不要解释成已经证明它具有最高商业价值。

3 分钟很紧时，不展开长宽高、全部来源详情和能力说明弹窗。保留四个关键画面：缺事实阻断、人工确认成功、红色风险拦截、修订后仍需重审。

## B. 5 分钟版本

| 时间 | 展示重点 | 建议讲述与操作 |
| --- | --- | --- |
| 0:00–0:30 | 问题与边界 | 说明“供应商怎么写，不代表商品就能怎么卖”。打开右上角“演示能力说明”，指出左侧是本地真实操作，右侧是仍在模拟的智能和外部数据，再关闭。 |
| 0:30–1:10 | 文件导入与数据质量 | 实际选择 XLSX，展示预览 8 / 6 / 1 / 1 / 0；解释重复跳过、缺资料保留。确认导入，看到 7 个商品。可展开一条重复记录，说明不会用后面的 USD 99 覆盖主角 USD 8.20。 |
| 1:10–1:55 | 缺重量闭环 | 打开 `LM-KT-IMP-005-BLK-500`，先看 Pricing Blocked。进入“核对事实”，缺失字段在前面；补 0.42 kg，保存后明确停在待确认，确认后展示持续的绿色反馈。展开来源查看原文件位置、原值 Missing 和人工确认时间。 |
| 1:55–2:30 | 可解释选品 | 左侧进入上新任务，说明固定需求和匹配理由。选择主角完成后半段。强调固定打分目前用于演示流程，没有运行推荐模型。 |
| 2:30–3:10 | V1 / V2 与事实使用权限 | 点“分析证据”，系统折叠长版本详情，把定价和 Fact Review 提前。需要时展开“查看 V1 / V2 详情”：基础值没有被 V2 覆盖。说明 Confirmed 是事实决策状态，Allowed 是文案使用权限，成本和重量即使确认仍不可用于消费者文案。 |
| 3:10–3:45 | 文案与来源 | 生成 Amazon 文案，事实来源入口就在标题下方。指向颜色、容量的文件来源，以及带 Mock 标识的补充字段。说明英文来自模板，美国站文案保持英文。 |
| 3:45–4:30 | 风险与修订 | 指出独立风险注入的 100% leakproof，运行审核，展示 HIGH RISK / Publish blocked。应用建议修订后，特意停在黄色 Review required，展示发布仍禁用；再审才变为绿色可发布。 |
| 4:30–5:00 | 输出与收束 | 发布并下载 CSV。Shopify 分支留作问答，需要另行生成、审核和模拟发布后才有草稿结果。最终表达：“我们先把来源、人工决定与发布条件连起来，再逐步替换 Mock 能力。” |

不要在 5 分钟内强行展示所有字段编辑、CSV 和 XLSX 各导入一遍、两个平台完整发布两次。保留这些作为评委追问时的备用操作。

## 现场回退

- 文件选择或样例路径不方便时，点击“载入内置数据”。说明使用内置样例继续演示，不要假装刚才完成了文件导入。
- 内置缺重量 SKU 是 `LM-KT-BTL-005-BLK-500`，补 0.42 kg 后售价为 **USD 19.20**；导入样例缺重量商品售价为 **USD 18.90**。两者成本不同，不要混说。
- 点错了步骤可以用左侧工作区返回；页面顶部仍显示任务、SKU 和当前状态，现有进度条下面给出下一步提示。
- 修改事实会清除旧文案、审核和发布；这是预期行为。重新生成、重新审核后再发布。
- “重置演示”用于彻底重新开始，不用于在导入目录中返回首页。
- 如果需要转用截图，使用 `docs/截图/` 的实际 UI 截图，并明确说“这是此前实际运行的画面”。

## 不要使用的表述

- “AI 已经读懂这些图片 / PDF”：目前补充提取仍是 Mock。
- “94% 的把握这款能卖好”：94 是规则匹配分，没有销售预测含义。
- “Confirmed 就代表有真实检测认证”：它可能来自预置演示状态或操作人员确认。
- “系统已经给 Amazon 上架了”：只完成模拟发布和本地 CSV。
- “修一下就自动通过了”：必须重审当前文案版本。
