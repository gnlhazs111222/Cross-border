## 3. 当前架构与数据权威来源

```text
React Web
  → 统一 apiClient
  → Fastify / Cookie Auth / Zod
  → Domain Services
  → Prisma / SQLite
  → Provider
      Recommendation：Mock
      Evidence：Mock
      Listing：Template 或显式开启的 Qwen
      Review：Rules

Offline Competition Mode
  React → 原 mockApi → localStorage
```

服务端权威保存：User、Session、Product、LaunchTask、TaskSelection、FactCard、Fact、Evidence、ListingDraft、ReviewResult、PublishResult、AiCall。

Full Demo 浏览器只保存语言、平台 Tab、页面等 UI 状态和非权威业务快照。刷新会用 API 结果覆盖；清空 localStorage 或使用只有有效登录 Cookie 的新浏览器环境，仍能恢复数据库中的事实、文案、审核与发布。

伪造 localStorage 不能把未通过审核的数据库文案变成可发布。正常业务请求不接受客户端伪造的 userId、reviewPassed、publishAllowed 或任意可信事实数组。

## 4. 已实现的业务流程

### Materials 与任务

- 真实解析固定 14 列 XLSX / CSV，保留替换资料集、追加新 SKU、逐行错误和精确 SKU 去重。
- 导入商品写入当前用户 SQLite；保留文件名、工作表、行号及字段来源。
- 提供 10 个内置商品回退，以及可以真实上传的示例文件。
- 固定上新任务、候选池与 Top 3 推荐仍使用原确定性评分，尚无自由任务编辑或 AI 推荐。

### Facts 与人工核对

- 服务端生成 V1 的 11 个基础字段；Analyze 通过 MockEvidenceProvider 保存独立 V2。
- V2 增加包装内含、表面工艺、杯盖和待确认防漏宣称，不覆盖 V1。
- Edit / Add、Confirm、Reject 均写入数据库，保留原值、原来源、人工来源、时间与 revision。
- 编辑后先进入 Requires Confirmation，不能自动获得消费者文案使用权。
- Confirmed 表示供应商基础字段或人工确认状态，**不等于独立核实商品真实性和性能**。

### Pricing

- 根据服务端已确认的重量、尺寸和采购成本判断是否可以定价。
- 缺重量 → 补 `0.42` → 保存后仍待确认、仍阻断 → Confirm 后才解除阻断。
- 内置缺重量商品算得 USD 19.20，样例导入缺重量商品算得 USD 18.90；不是所有商品都写死 19.99。
- 运费、关税、平台费用和利润假设仍是 Demo 固定值，没有真实物流或税费服务。

### Listing、Review 与 Publish

- Amazon / Shopify 分别保存文案版本、审核和发布结果。
- 文案绑定 factsRevision；审核和发布绑定具体 Listing revision。
- 编辑文案只使该平台旧审核 / 发布失效；编辑事实会使两个平台都失效，保留历史记录。
- 过期版本写入返回 409。模型生成在数据库事务外执行，保存前再次检查版本。
- 发布由后端验证用户归属、最新文案、当前事实、有效审核和零高风险问题。
- CSV 由服务器读取有效 Amazon 发布结果生成；过期或跨用户下载被拒绝。
- Publish 仍为 Mock，固定演示 ID 不是实际电商平台商品。

## 5. 最新完成的真实 Qwen Listing

```text
SQLite 当前 Confirmed + Allowed Facts
  → QwenListingProvider
  → TextModelProvider.generateStructured
  → 百炼 OpenAI-compatible API
  → JSON / Zod 校验
  → 事实授权检查
  → Qwen 草稿或模板回退
  → ListingDraft
  → 显式规则审核
  → 后端模拟发布授权
```

Prompt 版本：`listing-qwen-v1`；默认模型：`qwen3.6-flash`。

仅把消费者文案允许字段、商品身份和必要任务信息交给模型。认证信息、内部采购成本、申报价值、运费税费、私有来源文件位置、未确认和已拒绝事实不会作为授权事实发送。

输出包括 title、bullets、description、attributes、usedFacts。校验检查字段与值对应、允许的容量格式、未知属性、新增数值、常见规格矛盾、内部商业内容及已知无依据宣称。

超时、HTTP 错误、非法 JSON、Zod 失败、授权失败、预算或输出 token 限制等情况会回退模板，并保存 generationMode、模型、Prompt 版本、inputHash、fallbackReason、aiCallId 等 metadata。失败不会直接断掉主流程。

每进程缓存最多 100 条成功结果，并合并同时到达的相同请求。缓存键含平台、任务、商品、允许事实、factsRevision、Prompt 版本和模型，不含用户凭据。缓存命中不再调用模型；重启后清空。

### 一个重要审核边界

RuleReviewProvider 没有变成 AI 语义审核。对 Qwen 文案，服务器保存通过结构与授权校验的原始输出作为比较基准，再显式检查 R001 和后续改写差异。人工修改不能篡改该基准，差异仍触发 R002。

这说明版本链与规则机制有效，**不证明所有 Qwen 文案都已经完成独立语义核查**。usedFacts 也只是待检查的模型输出，不能单独证明正文每一句都真实。

### 两次真实验收

| 平台 | 模型 | 延迟 | 输入 / 输出 / 总 tokens | 结果 |
| --- | --- | ---: | ---: | --- |
| Amazon | qwen3.6-flash | 2384ms | 642 / 526 / 1168 | 校验、规则审核、模拟发布通过，无回退 |
| Shopify | qwen3.6-flash | 2675ms | 646 / 497 / 1143 | 校验、规则审核、模拟发布通过，无回退 |

主角 SKU：`LM-KT-BTL-001-BLK-500`；factsRevision=2，允许字段 8 个。两份输出未观察到新增规格或绝对防漏宣称。只有两个真实样例，不能据此估算模型整体质量、误报漏报率或平台合规效果。
