# 比赛版本 UX Audit

日期：2026-09-08。基线：`b47b061`，工作分支：`pyc`。没有重写稳定提交，没有改动业务服务、数据模型、评分、定价公式或发布条件。

## 审计方法

先在原版实际运行页面上，从重置、载入内置目录、导入 XLSX 开始，点击到 Top 3、主角、V2、Listing、R001、修订、重新审核、模拟发布、CSV 下载，再走缺重量商品补 0.42 kg 的支线。记录首次用户在 1440×900 视口下看到的布局和按钮位置。

初次点击全程无 pageerror，但存在影响讲解节奏的信息布局问题。以下坐标是英文界面、页面滚动到顶部时测得，不是估计值。

## 发现及修复

| 审计发现 | 原版观测 | 本轮修复 |
| --- | --- | --- |

| V1 / V2 详情挤压后续工作 | 分析后 Fact Review 顶部约 1582px | 分析后默认折叠长版本对照，保留可展开的原详情；新增次级“核对事实”锚点，主按钮仍是原有下一步动作 |

| Confirmed 容易被理解成可直接发布 | 权限含义需口头补充 | 表格前明确区分事实状态与文案使用权限：确认后的成本、重量仍仅内部使用 |

| 小屏幕先展示长文案、再看到风险 | 审核侧栏原先在文案之后 | 小屏幕先展示审核区，首屏提供风险总提示；桌面仍是原来的双列工作区 |
| Real / Mock 分散在多个说明中 | 需逐页解释哪些能力真实执行 | 顶部增加轻量 Demo Capabilities 弹窗，分 REAL / LOCAL 与 DEMO / MOCK 两组，无新设置页 |

| 内部状态词不够产品化 | 例如 initial、listing generated | 显示 Ready to start、Review required、Publish blocked、Ready to publish；内部 state 不变 |

| 弹窗关闭后焦点不明确 | 无显式 Dialog Trigger 时可能落到跳转链接 | 关闭后返回实际触发元素；若原元素已卸载则回主内容，不引起页面跳动 |
| 文案来源入口太靠后 | 原 Fact Sources 约在 1387px | 移到文案标题下方，展开后直接看到实际来源，再继续阅读卖点和描述 |

| 通知可能遮住右侧主操作 | Toast 固定在右下方 | 桌面通知移到内容区左下方，避免遮住审核 / 发布操作；通知正文不拦截底下点击 |

## 主操作层级

- Materials 保留“创建演示任务”为主要后续操作，导入和内置数据为次级入口。
- Top 3 只有主角的选择按钮是主要样式，其他候选为次级按钮。
- Evidence 保留顶部主要操作，版本详情内部的重复 Analyze 按钮改为次级；定价阻断时主要动作指向 Fact Review。
- Fact Review 每行编辑 / 确认为局部次级操作，Dialog 中保存是唯一主要动作。
- Review 未审核时突出 Run Review，阻断时突出 Apply Suggested Fix，通过后突出 Publish。

## 保留的业务语义

- 仍然先保存为待确认，再 Confirm，不提前解除定价阻断。
- 固定样例主角仍是 94 分，价格仍为 19.99。
- 内置缺重量商品确认后 19.20，导入缺重量样例确认后 18.90。
- 确认与文案使用权限依然分开；风险注入依然独立于正常事实授权。
- Apply Suggested Fix 不会自动产生 Passed；事实变化后旧结果仍然失效。
- 真实文件输入、人工操作、规则和 CSV 的本地执行，与推荐智能、补充提取、外部费率和平台发布的模拟边界保持清楚。

## 回归方法

保留原有 22 项测试，仅把旧显示文案 `initial` 的断言更新为产品文案 `Ready to start`；原始状态历史、阻断、修订和发布断言没有删除或放宽。

增加中英文 × 1440×900 / 1920×1080 / 375×812 六组演示验收，覆盖：

- 主链与缺重量支线均通过真实点击运行。
- 页面无整体横向溢出，能力说明弹窗在视口内，关闭后焦点正确返回。
- 能力说明不修改业务 state。
- 桌面 Top 1 选择按钮完整位于首屏，风险提示与主要修订动作可见。
- 修订后是待审核，发布仍禁用；重审通过后才启用。
- 人工确认后有持续成功反馈，并显示实际按成本计算的 18.90。

## 最终验收结果

实际执行 `npm run typecheck`、`npm run build`、`npm run test:e2e`，全部通过：**28 passed (26.9s)**。原有 22 项保留，新增 6 个语言 / 屏幕组合；没有新增业务服务、数据模型或依赖。

三种屏幕均完成中英文主线与补重量支线。英文 1440×900 实测：Top 1 按钮顶部约 841px、底部约 880px；Fact Review 顶部约 867px；主要修订按钮顶部约 591px。中文同尺寸的 Top 1 按钮底部约 889px，完整位于首屏。

曾在严格断言中发现中文 1440 下按钮底部超出约 3px，已缩短非关键留白并重跑全量测试；没有降低“完整可见”的要求。

11 张 PNG 已逐一检查文件头，全部为 1920×1080。已查看 Top 3、人工确认、风险拦截和文案来源等实际截图，并补上讲稿中的回退和同分情况说明。

另在用户使用的 5173 页面核对讲稿的实际点击顺序：先修复导入缺重量商品得到 18.90，再进入上新任务选主角，完成 19.99、R001、修订、重新审核、模拟发布和 CSV 下载。

本轮没有改动 `src/services/`、`src/types/` 或 `src/data/` 的业务实现，没有新增业务模块。代码在 `b47b061` 后创建独立提交，不改写原稳定历史；原先未提交的进度文档及未跟踪文档保留在本地，不混入本轮提交。

验收结论只覆盖当前 Demo 和三种要求的屏幕，不代表真实 AI、真实外部报价、平台上架或生产级跨浏览器验证。达到本轮停止条件后不继续新增功能。
