## 2. 当前完成的产品闭环

```text
登录
→ 真实固定模板 Excel / CSV 或内置商品
→ 字段校验、精确 SKU 去重、候选资格判断
→ 创建/编辑任务需求
→ 规则或 Qwen 排序，展示 Top 3 与理由

→ 分析模拟补充证据，形成独立 V2

→ 读取任务级税价快照，判断定价就绪并计算模拟售价

→ 编辑新版本
→ 规则或 Qwen 语义审核
→ 拦截/人工修订/重新审核
→ 当前版本通过后模拟发布
→ Amazon CSV 下载、刷新恢复
```

它不是只有静态页面：文件解析、数据库保存、任务编辑、事实状态变更、版本失效、下载文件均真实执行。智能推荐、生成和审核支持可选 Qwen；证据补充、物流税费及平台发布仍有明确模拟边界。

## 3. 技术与持久化

React + Vite + TypeScript + Tailwind；Fastify + Zod；Prisma + 本地 SQLite。原五个工作区仍保留。

用户、商品、任务、任务级税价快照、选中关系、事实、证据、文案、审核、模拟发布及 AI 调用元数据保存到服务端数据库。浏览器保存语言、页面等偏好及非权威缓存；不是只依赖 localStorage 的旧版本。认证使用 HttpOnly Cookie，商品/任务按用户归属访问。

Key 存于本地服务端环境，不进入本说明、前端或 Git。不同电脑不会因拉取代码自动获得另一台机器的数据库、验收任务或凭据。未接入真实电商发布、云数据库、生产部署和完整多用户管理系统。

## 4. 入口数据与事实能力

### 固定模板导入

真实支持 `.xlsx` / UTF-8 `.csv`，固定 14 列：

```text
sku, productName, category, color, capacityMl, material, hasStraw,
countryOfOrigin, supplierCost, declaredValue, packagingWeightKg,
packageLengthCm, packageWidthCm, packageHeightCm
```

没有智能猜测表头；列不匹配会明确拒绝。支持预览、逐行错误、替换目录或仅追加新 SKU。包装重量/尺寸缺失的商品可保存并参与选品，但选中后定价仍会阻断；同 SKU 重复行跳过，不覆盖首条有效记录。
除必填 14 列外，还识别两组可选列：物流申报 `liquid` / `battery` / `magnetic` / `aerosol` / `flammable` / `fragile`，质检报告 `reportNo` / `reportResult` / `reportValidUntil` / `reportCapacityMl` / `reportMaterial`（`reportNo` 留空 = 该 SKU 没有质检报告，静默不报警）。其他认不出的列名会被忽略，不会让整表失败；但质检报告有效期必须是 `YYYY-MM-DD`，写错该行报 `Unsupported format`。

样例：

- `public/demo/prismlaunch-supplier-demo.xlsx`
- `public/demo/prismlaunch-supplier-demo.csv`
- `public/demo/prismlaunch-bag-demo.csv`

水杯两份样例都是 8 行：6 条完整、1 条缺包装重量、1 条重复；默认替换后保存 7 个商品。包类 CSV 是一个可完整走通的黑色帆布托特包，容量和吸管字段可留空。10 个内置商品随时可恢复。样例导入与 reset 会清除相应任务及下游进度，测试前应保存需要保留的结果。

### Fact Review

V1 保存基础事实，V2 保存增强事实，不覆盖 V1。来源区分供应商文件、Mock 证据与人工确认。人工编辑先进入待确认，必须再确认；支持拒绝和补齐。未确认、缺失、拒绝、禁止公开的事实不能进入正常文案。

导入的文件值/行号是真实来源记录；没有通用 OCR 或文档解析，V2 新增字段是标注为“模拟分析”的演示样例，PDF／图片不做解析（商品图片另有图片核对，只标一致／不一致）。Confirmed 是当前授权状态，不是产品检测认证。

缺重量支线：内置 `LM-KT-BTL-005-BLK-500` → 核对事实 → 包装重量补填 0.42 → 保存 → 确认 → Pricing Ready，模拟建议价 USD 19.20。导入样例中的缺重量商品是另一个 SKU `LM-KT-IMP-005-BLK-500`，补齐后 USD 18.90。两者均不是强行套用主角 USD 19.99。

### 任务级税价快照

创建任务时会在 SQLite 中保存一份 `PricingSnapshot`，冻结快照 ID/版本、平台与市场、参考汇率来源和日期、运费配置、关税规则、平台费配置及创建时间。售价计算只读取当前任务的最新快照。修改平台、市场或类目会生成新版本；手动刷新也会生成下一版，并使旧发布结果失效。当前金额仍来自固定 Demo 配置，不是实时商业报价或税则查询。

## 5. 选品：已经实现什么

### 两步判断

1. **候选资格由代码决定**：排除重复/疑似重复、类目不匹配、不支持的商品类型，以及缺少品类核心事实的商品。包装重量、尺寸、采购成本等定价资料和最低利润目标不参与过滤或排序。当前完整上新工作流支持水杯和托特包；台灯继续明确排除。
2. **只在合格集合内排序**：规则或 Qwen 返回最多 3 个 SKU，分数、匹配理由与不足。颜色、容量、吸管等偏好通常影响排序，不是全部作为硬性排除条件。

任务可编辑平台、市场、类目、自然语言要求和最低单位利润。保存不调用模型；任务变化使旧推荐与下游结果失效。相关事实变化后也必须重新运行推荐。

### 规则与 Qwen 的区别

- 规则：有限关键词/数值偏好和固定权重；水杯支持颜色、容量、吸管、材质，托特包支持品类、颜色、材质等基础匹配；不能完整理解任意复杂需求、优先级或风格。
- Qwen：从合格商品和已确认公开事实生成排序及解释，不做实时市场调研，不接销量、趋势、竞争价格或广告数据。
- 商品必须来自输入候选，数量、SKU/ID、分数范围、顺序和部分核心事实理由会校验。模型不能把已排除商品加回来。
- 超时、格式/引用/理由校验失败或预算不足时回退规则。超过 40 个合格候选也回退规则。
- 结果保留 `rule` / `qwen` / `rule_fallback`、模型、Prompt、调用 ID、失败原因与缓存标记。成功输出可缓存，刷新只读，不发新请求。
- 分数是相对任务匹配程度，不是模型置信度、销量预测或商业收益。

**关键操作差别：创建演示任务/载入演示任务固定走规则。测试真实 Qwen 时，需要启用真实配置，然后在上新任务页点击“运行推荐”，并检查结果实际标为 Qwen；回退结果不能算作模型成功。**

## 6. 文案、审核与发布现状

文案生成支持模板和 Qwen，从获准事实出发；可编辑并保存新版本，分别保存 Amazon/Shopify。Qwen 生成失败可回退模板，应查看文案生成来源。采购成本、申报价值不用于正常消费者文案。

审核当前实现版本为 `review-qwen-v13` / `review-hard-v11`：

- 本地硬规则加可选 Qwen 语义审核，问题包括规格冲突、无依据宣称、未授权事实、内部信息。
- 校验结构、问题原句、位置、事实字段引用，以及部分理由/数字来源。合理改写不必与模板逐字相同，但模型仍可能误报、漏报或返回不合要求的结构。
- 状态有 passed、blocked、needs_human_review、failed、running；只有有效 passed 才允许发布。
- 审核失败不会悄悄回退为规则通过。建议只是展示，语义模式下按建议到文案工作室人工修改，再审核。
- 事实、任务、文案版本或审核配置变化，旧批准不能继续沿用。重审开始也会撤销旧批准/发布；发布及 CSV 下载再次由服务端验证。

B 第三轮历史报告：16 条新合成输入首次状态匹配 16/16；11 个预期问题均匹配；15 次模型调用、26455 tokens，1 条由本地规则拦截。**输入和答案由知晓开发历史的 AI 起草并复核，人工复核数为0**，不是独立人工盲测、总体100%准确率或重复调用稳定性证据。此前真实页面也发现过格式、定位失败，保留了失败和后续修复记录。

详情见 `docs/B_REVIEW_DEMO_HANDOFF.md`、`docs/B_REVIEW_ROUND3_ACCEPTANCE.md`。不要把早期 v8 文档当作当前版本。

发布仍为 Mock：Shopify 显示模拟草稿记录，Amazon 可以下载真实 CSV，但不是已经验证的官方上传模板，也没有向电商平台创建真实商品。

## 7. 如何测试整个演示

### A. 先验证稳定主链路

登录 → 导入 Excel 样例 → 确认7个商品 → 创建演示任务 → Top1主角 → 分析证据 → 定价19.99 → 模板Amazon文案 → R001拦截 → 应用建议修订 → 重新审核 → 模拟发布 → 下载CSV → 刷新恢复。

这是规则/模板模式的路线。首次模板 Amazon 会故意注入 `100% leakproof`，用于展示风险拦截，不是正常事实授权的结果。若文案已使用真实 Qwen，不保证自然生成这句；不应为了演示而把生成正常文案视作失败。

### B. 再测真实模式的整条链路

启用 Qwen → 新建/编辑任务 → 保存 → **运行推荐** → 查看 Qwen来源或回退原因 → 选择 SKU → 分析/确认事实 → 生成文案并查看生成来源 → 审核并查看审核追踪 → 按结果修订重审 → 模拟发布/CSV。

可以在正确500ml文案通过后，只把标题改成750ml：保存后旧审核立即失效；再次审核预期发现容量冲突。再改回500ml、保存、重审。真实模型可能 failed 或转人工复核，这要记为实际结果，不能反复点到成功后称首次通过。

### C. 选品手动对照测试

先固定同一份目录和已确认事实，每次只改需求中的一个条件。下列前三项可直接使用内置或样例商品；这里是事先预期，不是本轮已经运行的 Qwen 结果。

| 需求 | 应重点观察 |
| --- | --- |
| `Black 500ml stainless steel bottle without a straw.` | 主角001应优先，理由不能编造性能 |
| `A black 500ml commuter bottle with a straw.` | 有吸管002应优先 |
| `Black 750ml stainless steel bottle without a straw.` | 750ml的003应优先 |
| `Ivory 500ml stainless steel bottle without a straw.` | 象牙白004应优先 |
| 玻璃或当前目录不存在的规格 | 明确说明不匹配和取舍，不能把不锈钢说成玻璃；不一定应返回空，因为材质偏好不是现有硬过滤 |
| 最低利润从5改成10 | 推荐候选和排序不应变化；选择 SKU 后，建议售价应按 USD 10 的目标利润重新计算 |
| 缺包装重量、重复商品 | 缺重量商品仍可参与选品，但选中后定价阻断；重复/疑似重复商品仍必须在排序前排除 |

之后再设计优先级冲突、风格偏好、近似规格等更难样例。必须先写下可接受的 Top1/备选和理由标准，再看模型结果，避免事后把任何排序都解释为正确。

记录：输入需求、候选目录/事实版本、预期、实际Top3、结果来源、理由是否忠实、回退/错误、模型/Prompt、调用ID、延迟、token、缓存命中。规则和 Qwen 必须用同一批输入；将模型成功率、回退率和最终系统交付质量分开统计。

重复点同一需求可能命中成功缓存，不是多次独立模型运行。如需独立重复性评测，应设计明确隔离缓存的受控测试；不要仅用多次点击就报告稳定性。

```dotenv
AI_LIVE_ENABLED=true
RECOMMENDATION_PROVIDER=qwen

REVIEW_PROVIDER=qwen
```

使用现有本地后端 Key，修改配置后重启 API。每个后端进程共享最多20次真实尝试，失败也计数；SDK不自动重试，默认30秒超时。刷新、查询、保存任务、发布及下载不调用模型。实际点击推荐/生成/审核可产生费用；本说明不附带任何凭据。

无网络评测命令：`npm run eval:recommendation -- --provider rule`。

真实推荐 CLI 是受限开发工具：需显式 qwen-live、每次最多4例，有累计调用限制并会复用已经记录的成功结果。运行前应阅读 `evaluation/recommendation/README.md`，不要把它当无限制全量测试器。常规手动演示可先使用页面，但仍要记录来源和缓存。

## 10. 希望网页版 GPT 帮助做什么

请基于这些实际能力，为用户设计一份能亲自执行的测试计划，重点是完整演示与选品表现：

1. 区分规则链路验收、真实模型接入验收、排序效果评估，分别定义通过标准。
2. 先安排6～10个手动任务，覆盖简单匹配、偏好冲突、不存在的属性、无候选、补齐后的重新入选；不要只重复主角任务。
