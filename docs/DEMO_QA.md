# PrismLaunch 比赛问答

以下回答以当前代码实现为准，适合现场直接回答。不要把规划中的能力当作现状。

## 1. AI 在哪里？

当前没有调用真实 AI 模型。推荐采用固定评分，补充证据采用预置 Mock 字段，英文 Listing 使用模板，审核使用本地规则。这个版本展示智能上新应如何经过资料、事实、人工确认和发布门槛；模型接入尚未做。

## 2. 哪些能力目前是真的？

浏览器真实读取固定模板 XLSX / CSV、校验字段、检查精确 SKU 重复、保存人工编辑与确认、执行状态变化和旧结果失效、按公式计算价格、拦截不合格版本、生成可下载 CSV。这些操作实际执行，并经过自动化测试。

“真实本地逻辑”不代表演示样例来自真实客户，也不代表已经连到线上平台。

## 3. 哪些是 Mock？

推荐智能、PDF / 图片补充提取、运费、关税、平台费用、文案智能和平台发布均为模拟或固定假设。右上角“演示能力说明”把这些边界集中列出。当前业务 API 没有外部请求。

## 4. 为什么 Top 1 是这个商品？

在未人工修改的样例里，主角是黑色、500ml / 16.9 fl oz、无吸管、包装信息齐全，符合固定任务要求。第二款带吸管扣 12 分，第三款 750ml 扣 16 分。资料缺失、重复、疑似重复和类目不符的商品不进入推荐。

如果人工补齐另一只同条件水杯，它也可以得到 94 分；同分时代码按固定规则优先主角 SKU。这是为稳定演示设置的顺序，不是已经验证的商业最优选品。

## 5. 94 分是什么意思？

当前规则以 94 为完整匹配的起点，再对吸管、容量和颜色扣分。它不是概率、模型置信度或市场销量预测，也不是基于真实效果评估校准的分数。

## 6. Evidence 是否真的解析了？

导入的 XLSX / CSV 字段是真实解析的，V1 保存文件名、工作表和行号。证据区只有这一条供应商表格；PDF 与商品图片都不会被解析，V2 新增字段标注为“模拟分析 · 演示样例 · 未解析任何文件”（商品图片另有图片文字核对，只核对图上印字与事实是否相符）。字段有一个来源位置，不代表供应商宣称已经被独立核验。

## 7. Confirmed 是谁确认的？

要看来源。内置和样例主角的一部分确认状态是预设的演示状态；人工操作产生的记录显示 Manual Confirmation，并保存前值、原来源和确认时间。导入行字段通过固定模板的数据确认，也不等于产品检测。

当前没有登录和人员身份系统，因此人工确认记录的是当前浏览器操作，不构成完整的实名责任链或审计系统。

## 8. Confirmed 和 Allowed 为什么分开？

它们回答不同问题：Confirmed 是事实当前的决策状态；Allowed 表示是否可以用于消费者文案。采购成本、申报价值、包装重量和尺寸即使确认，也只用于内部判断，不会写进消费者文案。正常生成必须同时满足 Confirmed 和 Allowed。

## 9. 为什么 100% leakproof 还会出现？

首次 Amazon 草稿故意注入这句话，用来测试风险拦截。UI 明确说明它是独立的 Demo risk injection，不是经过事实授权的正常字段，也不是本版本真实 LLM 产生的幻觉。运行审核后，它会触发 R001。

## 10. 为什么不用 LLM 直接生成英文 Listing？

LLM 可以承担文案生成，但生成并不能替代资料完整度、字段权限、来源核查和当前版本审核。本 Demo 先把这些约束做成可运行的流程，目前还没有接入 LLM。不能据此宣称已经测过 LLM 生成质量。

## 11. 是否真的支持 Amazon / Shopify？

支持两个平台的演示文案和相互独立的模拟审核 / 发布结果。Amazon 可以下载演示 CSV；Shopify 显示 `SHOP-DEMO-1042 / Draft`。没有实际创建线上商品，没有调用平台 API，CSV 也不是已通过官方验证的上传模板。

## 12. 修订以后为什么必须重新审核？

原来的通过结果属于原文案版本。保存修订不等于新版本合格，所以先回到 Review required，再运行审核。事实发生变化时，两个平台的旧文案、审核、发布也会失效，不能继续拿旧结果发布。

## 13. 缺重量为什么要阻断？

重量是定价流程所需的包装事实。如果缺失，不能假装知道物流输入已经完整。保存 0.42 kg 后仍要人工确认；确认后，实际本地逻辑重新判断必要条件，才解除阻断。

这里的物流费仍固定为 USD 3.10，没有根据 0.42 kg 查询真实运价。不能说“输入重量就自动获取了真实物流报价”。

## 14. 为什么补齐后是 18.90 或 19.20，不是 19.99？

商品成本不同：导入缺重量样例的采购成本为 7.90，内置缺重量样例为 8.20；再加上模拟运费 3.10、关税 0.70、平台费 2.20 和目标利润 5.00，分别得到 18.90 和 19.20。19.99 是主角样例的演示定价设置，不是所有 SKU 的固定答案。

## 15. 为什么需要 V1 / V2？

V1 组织基础事实，V2 在该基础上补充任务相关事实，便于区分输入资料和增强结果。分析 V2 不覆盖 V1；明确的人工基础字段修改会更新 V1，并同步 V2 继承的基础字段；只修改 V2 增强字段不会反写 V1。它们目前是浏览器状态中的对象，不是完整的数据库版本系统。

## 16. 能导入任意 Excel 吗？

不能。当前必填的是固定 14 个列名，区分大小写、可调列顺序；XLSX 只支持单工作表，CSV 为 UTF-8 逗号分隔。文件最多 2 MB、500 行，公式不支持。缺必填列会提示 Unsupported supplier template，不做语义猜测；另外识别的可选列（图片引用、物流申报、质检报告）会被读取，其余列名忽略而不是整表拒绝。

## 17. 重复商品怎么处理？

文件导入按精确 SKU 去重，保留首个有效记录。“替换”只处理本文件内重复；“仅添加新 SKU”还检查现有目录。重复行不覆盖已有成本。疑似重复标签属于内置演示数据，并没有新增图片或语义去重算法。

## 18. 审核能识别所有风险吗？

不能。R001 检查已知的 `100% leakproof`，R002 拦截与确认模板不同的改写。这样可以演示明确的阻断行为，但也可能拦截合理改写。它不具备通用语义审核、平台政策全覆盖或合规认证能力。

## 19. 下一步如果接真实系统，优先做什么？

先选一类商品和一组真实供应商资料，明确证据提取、冲突与人工确认的验收标准，再逐步替换 Mock。真实推荐、语义审核和平台发布分别需要效果评估及接口验证，不能只替换一次模型调用就视为完成。这是后续方向，本轮没有继续开发这些功能。

## 20. 你们验证了什么？

原有 22 项测试覆盖导入、事实确认、价格、文案、阻断、修订、发布和恢复。本轮额外按中英文 × 三种屏幕检查整个演示故事、能力说明弹窗、按钮可达性、状态反馈和页面溢出。最终共 28 项测试通过（原有 22 项 + 6 个语言 / 屏幕组合）；详情见本轮 UX Audit 记录。测试通过不等于证明真实 AI 或真实平台能力已落地。
## 21. 图片文字核对是什么？

它是 C 线模块 4「多模态解析与事实卡更新」：读商品图上**印的文字**（容量、产地、材质等），和我们的商品事实比一比是否相符，结论只作为标注挂在 v2 卡片上，不改 v1、不自动确认任何东西。不一致时**在那一行直接写出问题**——图中印字 vs 我方事实——下面给三个选项：直接保存图中印字（写进 v2，仍须人工确认）、修改后保存（自己填第三个值）、放弃该图（这张图从该 SKU 的核对里剔除，重跑不再读取）。一致的先不动，只标徽标和图中原文引用。

它只读文字、不判外观：颜色不对、多了吸管都不会报；图上印的 `100% leakproof`、`BPA FREE` 这类性能／安全宣称永远不能变成事实，最多成为一条“待确认的机器观测”。默认离线运行（不发请求），显式切 `qwen` 才调视觉模型；调用失败会降级为离线判定并写明错误码。

## 22. 质检报告和物流属性也会报警吗？

会，三条核对在同一个「核对与报警」面板里，格式与下面的事实核对表一致：**一张表，表头一行是三个核对、一个核对一列**（图片文字核对｜质检报告｜物流属性确认），每列的格子里就是这条核对查出了什么、以及关掉它要点的按钮；规则统一为**正常静默，异常才报警**，报警的那一列整列按严重度着色、列头带警示图标，标题徽标给出报警条数。质检报告来自供应商表格的可选列，**没有报告会直接报警并关掉「继续到文案工作室」**（面板里点「提交质检报告」登记一份即可放行，不需要重新导入）；过期、与事实不一致会被点名（可以采纳报告值、换一份报告或放弃该报告），报告结论是“不合格”则永久阻断发布、不可放弃。物流属性按申报判定：禁区品、缺 UN38.3／MSDS 等资料时报警并要求补齐，已申报且无风险时静默成一行。图片上的印字不会影响危险品判定——`flammable` 的行，图上写 `NON-FLAMMABLE` 也没用。
