# 任务级税价快照

当前实现把原先页面上的固定“演示定价卡”改成了可持久化、可追溯、可版本化的任务级 `PricingSnapshot`。

## 创建与读取

- 创建上新任务时同时写入 v1 快照。
- 升级已有数据库时，migration 会为历史任务补建 v1。
- 修改任务的目标平台、市场或类目时创建下一版；只修改需求文字或最低利润时沿用原快照。
- `GET /api/tasks/:id/pricing-snapshots` 返回该任务的快照历史。
- `POST /api/tasks/:id/pricing-snapshots` 使用 `expectedVersion` 显式刷新，采用乐观版本检查，不能用旧版本重复刷新。

## 当前冻结的字段

每个快照保存：

- 快照 ID、任务、版本、平台、市场、创建时间；
- 结算币种；
- 参考汇率的币种对、数值、来源、参考日期和抓取时间；
- 运费金额、配置版本和来源；
- 关税金额、规则版本和来源；
- 平台费金额、配置版本和来源；
- 整体定价政策版本。

当前供应商成本已经按 USD 保存，所以 `CNY/USD` 只作为来源口径展示，不再次换算采购成本。

## 与售价和发布的关系

选中 SKU 后，售价计算读取当前任务的最新快照，而不是读取代码中的另一套临时金额。发布记录保存所使用的 `pricingSnapshotId / code / version`。

显式刷新快照后：

- 商品事实、Listing 和已通过审核继续保留；
- 旧发布记录立即失效；
- 页面读取新快照重新计算建议售价；
- 需要使用新快照重新执行模拟发布，之后才能下载 Amazon CSV。

## 演示边界

当前数值来自受控的固定 Demo 配置：运费 USD 3.10、关税 USD 0.70、平台费 USD 2.20，参考汇率为 `1 CNY = 0.139 USD`，参考日期为 2026-09-01。

## 费用构成（按项目书环节 7 计算，不再用固定金额）

售价不再由三个常数相加得出，而是按项目书的输入（成本事实、重量尺寸、费用快照、最低利润）算出来：

| 项 | 算式 | 演示口径 |
| --- | --- | --- |
| 计费重 | max(实重, 长×宽×高 ÷ 除数) | 除数 5000（快递/空运口径） |
| 物流 | (首重 + 续重步数 × 步长) × 目的国系数 | `logistics-demo-v1`：首重 0.5kg USD 3.10、每 0.5kg USD 1.20，US 1.00 / GB 1.15 / DE 1.20 / JP 1.10 |
| 关税（第一道） | 申报价值 × 关税率(目的国+类目) | `duty-demo-v1`：US 家居 8.5%、US 箱包 9%、US 电子 4%、GB/DE 家居 12%，其余 8% |
| 进口税（第二道） | (申报价值 + 关税) × 进口税率(目的国) | `import-tax-demo-v1`：US 0%（无联邦 VAT）、GB 20%、DE 19%、JP 10%，其余 10% |
| 平台费 | 建议售价 × 佣金率 + 固定费 | `platform-fee-demo-v1`：Amazon US 15%，固定费 0 |
| 建议售价 | (成本 + 物流 + 关税 + 进口税 + 固定费 + 目标利润) ÷ (1 − 佣金率)，向上取整到分，再与演示保底价取大 | 保底价目前只对主角样例生效（19.99） |

汇率：成本事实若以 `CNY` 计价（值形如 `CNY 58.99`），按冻结汇率换算成结算币种；演示的供应商行都是 USD，所以这条分支当前不生效，汇率只作来源留痕。

上面四张费率表都是**演示口径**，各自带版本号（`logistics-demo-v1` 等），面板的「税费计算」会显示计费重、适用税率和目的国，「查看快照来源与版本」显示冻结口径。接真实数据源时替换这些表，历史快照不改写。

这证明的是“快照、版本、来源、复算和发布绑定”链路，不代表已经接入实时汇率、物流报价、海关税则或平台费 API。后续接真实数据源时，应替换快照创建时的数据 Provider，而不是改写历史快照。
