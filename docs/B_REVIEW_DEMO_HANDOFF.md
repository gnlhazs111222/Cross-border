## 演示前准备

1. 使用基线提交及配套本地数据库；Git 不包含密钥和数据库，队友拉取代码不会自动获得本机验收任务。
2. 打开 http://localhost:5175/ ，正常登录，不进入离线比赛演示。
3. 本机独立任务为 `B-ACCEPT-1788879026672`，选择 Shopify，SKU 为 `LM-KT-BTL-001-BLK-500`。整理时最后实测是文案第 10 版、事实第 2 版、任务第 1 版。后续编辑会递增文案版本，不必追求固定版本号。
4. 检查事实容量为 `500ml / 16.9 fl oz`，已确认并允许用于文案；不要为了匹配文案而修改事实。
5. 在“审核与发布”确认“当前审核配置：规则 + Qwen”。展开追踪信息，检查模型与版本。当前为 `qwen3.6-flash / review-qwen-v8 / review-hard-v6`。
6. 检查调用额度、模型配置和网络可用；每次主动审核可能产生费用。本脚本最多主动审核三次，另有明确失败处理。
7. 不点击“重置演示”“载入内置数据”或“根据事实重新生成”。本轮展示审核能力，不需要重新生成整份文案。

本机演示登录信息显示在登录页。对外展示时不打开 `.env`，不展示密钥或完整请求头。

## 约三分钟的演示脚本

| 环节 | 操作 | 预期与讲解 |
| --- | --- | --- |
| 事实基础，约 20 秒 | 展示已确认容量与文案当前标题 `Black stainless steel bottle, 500ml` | “审核有明确的事实依据，事实卡是比较基准。” |
| 正常通过，约 30 秒 | 点击“运行审核”，等待完成，展开追踪信息 | “这是主动调用外部 Qwen 的审核结果；调用记录可以追踪。通过表示本轮范围内未发现问题。” |
| 旧授权失效，约 30 秒 | 前往文案工作室 → 编辑文案，仅把标题的 `500ml` 改成 `750ml` → 保存新版本 → 返回审核页 | “修改文案就产生新版本，上一版通过不能继续使用。”展示发布按钮不可用。 |
| 找出问题，约 40 秒 | 点击“运行审核” | 预期 blocked，问题是标题 `750ml`，类别规格矛盾，关联 `capacity`，建议改回 `500ml`。展示问题来源 Qwen 与发布锁定。 |
| 修正并重新批准，约 40 秒 | 标题恢复 `500ml`，保存；先展示发布仍不可用，再运行审核 | “修正不会自动批准，必须重审当前版本。”预期通过，发布恢复可用。 |
| 收尾，约 20 秒 | 刷新页面，查看当前版本与结果 | “审核结果保存在服务端，刷新不等于重新调用模型。这里的 Amazon / Shopify 发布仍为模拟。”停在通过状态即可。 |

网络等待时间可能超过上述安排。不要使用“注入演示风险”的 `100% leakproof` 来单独证明 Qwen 能力：这类已知风险可能被本地硬规则直接拦截，未调用模型。

## 现场遇到异常如何处理

| 实际状态 | 正确解释 | 下一步 |
| --- | --- | --- |
| blocked | 系统报告了具体风险 | 核对原句和事实引用，按证据修正文案并重审。 |
| needs_human_review | 证据不足或表达含糊，尚不能批准 | 补充证据或澄清文案；不能讲成“审核通过”。 |
| failed | 审核没有完成，不能据此判断文案正确与否 | 记录调用 ID、版本、错误码与追踪中的输出字段校验；保持发布锁定。 |
| passed 但旧授权失效 | 旧结果保留，但不能批准当前上下文 | 用当前文案、事实和配置重新审核。 |

若出现失败，先保留首次结果。现场时间允许时最多手动重试一次，并明确这是第二次尝试；再次失败则展示已有验收记录并结束实时审核部分，不切换 Mock 假装真实成功。

可用说明：“这次模型输出未完成校验，系统没有把失败当成通过，所以发布仍被锁定。我们保留了调用记录，后续按具体约束定位。”

`invalid_ai_json` 表示新实现中的 JSON 解析失败；`invalid_ai_schema` 表示字段校验失败。历史旧实现的 `invalid_ai_json` 也可能包含字段错误，不能把新含义直接套用到旧记录。

## A / B / C 对接边界

以下是供团队确认的建议，不代表已获得队友承诺。

- A 负责生成和编辑文案；保存时必须产生新版本，不能直接设置“审核通过”。B 通过现有服务端流程读取文案快照，不要求 A 直接调用模型审核器。
- C 负责证据入口、事实结构与确认状态；B 只把已确认且允许用于文案的公开字段作为支持证据。事实改变应递增版本并使旧审核失效。事实确认本身是操作决定，不是产品认证。
- B 负责审核提示词、输出校验、风险定位、审核结果展示、发布门禁联动及评测。扩品类时需与 C 核对公开事实字段范围，当前白名单不是任意品类自动全覆盖。
- 共同关注 `shared/review.ts`、`shared/contracts.ts`、`server/services/listings.ts` 和数据库模型。修改这些文件前同步变更范围，避免接口或版本失效逻辑被覆盖。
- 本轮 `79090f8` 没有数据库迁移；增加了可选的审核诊断元数据。尚未推送远程，团队接收版本需后续明确推送或合并。
