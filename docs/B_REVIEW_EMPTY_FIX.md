# 空建议与非最终审核条目修复

日期：2026-09-09。最终版本：review-qwen-v12 / review-hard-v8。

## 问题与原因

网站 v9 验收的 750ml 错误标题返回 invalid_ai_schema，定位 issues.1.suggestedFix: too_small。固定同一输入再次诊断成功复现：第一条正确报告标题容量矛盾，第二条却把正确的 Capacity 属性列为问题，在 reason 中自我推翻，并留下空 suggestedFix。因此不能只为第二条补一条建议，也不能把格式失败统计为识别成功。

原始网站调用未保存全文；[诊断捕获](../artifacts/b-review/empty-fix-diagnostic/diagnostic-1788949692387.json)是随后使用相同输入哈希的独立调用，不能视为原始响应原件。

## 最终修改

- 精简输出要求：issues 只包含有依据、可采取行动的问题，正确字段不生成条目；理由用简短结论，建议必须是非空修改或补证据行动。
- 加入“正确标题＋错误属性”和“错误标题＋正确属性”的对照示例，示例使用不同品类且声明不是当前商品事实。
- 请求中先提供 ALLOWED_FACTS，再提供 COPY。授权事实内容及筛选范围不变。此调整与最终提示词组合在本轮检查中改善了结果，不据此证明顺序对所有模型输入都有相同效果。
- suggestedFix 去除首尾空白后校验，拒绝纯空白建议。
- 修正 Wait, / Wait: 等自我纠正标记的边界匹配。仍为有限校验，不能识别所有自相矛盾表达。
- 无效响应整体 failed，问题列表为空且不能发布；没有自动删除可疑条目、补建议或自动重试。
