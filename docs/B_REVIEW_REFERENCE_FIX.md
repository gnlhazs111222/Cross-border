# 审核解释的事实引用完整性修复

2026-09-09；最终版本 review-qwen-v13 / review-hard-v9。

## 原因和修改

R2-09 的 v12 输出正确拦截隐含防漏承诺，但理由明确讨论 screw-top lid，factKeys 却为空。原有校验只确认已给出的引用存在、类别要求及数值来源，没有检查这种漏引。

提示词现在区分“支持宣称的证据”和“解释中讨论但不足以支持宣称的背景事实”：两者均应在 factKeys 中引用。无相关事实的 unsupported_claim 仍允许空引用，不能为了填引用而编造事实。

新增有限词面校验：在授权公开事实中，若一个完整的多词事实值唯一对应某个字段，且在 reason 或 suggestedFix 中明确出现，则必须引用该字段。匹配忽略大小写、标点和 Unicode 兼容差异，使用词边界。单词值、同值多字段及未授权事实不据此推断引用。没有自动补引，也没有扩大事实发送范围。

漏引返回 failed / invalid_review_reference，整体问题为空，无法授权发布。它不是成功识别风险；评测需将 failed 与 blocked 分开统计。事实键仍通过原有网站“关联事实”显示，不改变数据库或前端接口。

## 验证

- 捕获的旧 R2-09 输出回放：旧实现未拒绝漏引，新测试先失败；修复后拒绝漏引，而带 lidType 的相同输出仍为 unsupported_claim / blocked。
- 多词材料值、不讨论事实的解释、未授权值、同值多个字段对照均通过。
- 全量 112 项服务端测试通过，类型检查通过。
- 15 条开发案例状态全部符合预期，无技术失败。R2-09 正确引用 lidType，R2-07 仅报告错误属性；无依据护眼等未讨论具体授权事实的案例仍可使用空引用。
- R2-09 另作两次固定输入真实调用，与全量评测中的一次合计三次均 blocked、定位正确、引用 lidType，建议删除未经证实的防漏承诺。未自动重试。
- 本轮 16 次真实调用，28294 tokens；另有 1 条内部信息案例由本地规则拦截。

这些是参与开发的 AI 辅助案例，不是独立人工盲测。当前校验不能发现所有同义改写、部分值引用或不真实的语义推断，不能宣称所有引用完整性问题均已解决。引用某字段不等于该字段足以支持商品宣称。
