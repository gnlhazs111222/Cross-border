# B 审核定位、引用和模糊性修复

当前版本：review-qwen-v6 / review-hard-v4。

## 实现

- 输入附带 COPY_FIELDS，模型可直接复制准确的属性 key 和 bullet index，仍由服务端验证原句、位置与引用。
- 规格冲突必须引用已授权事实；未授权事实问题必须引用未授权字段。缺失或错误引用会失败，不会补造依据或回退通过。
- 提示词以事实卡为权威，只标注错误一侧；明确含混物理描述、确定风险优先于歧义、否定句不抵消后续性能保证。
- blocked 与 needs_human_review 均给出完整 JSON 示例，防止漏填 suggestedFix。
- 审核事实集合补充明确消费者字段 power / supply，仍需 Confirmed 且 allowed=true；不放开任意字段或内部信息。
- 版本变化使旧审核结果失效。未修改生成、数据库结构或页面。

## 验证

新增测试先失败、修复后通过，覆盖字段位置、冲突/未授权引用要求，以及功率/供电事实的授权和隐私隔离。最终服务端 102 项测试通过，类型检查通过。本轮未重跑浏览器测试。

[最终 60 条逐项结果](../artifacts/evaluation/review-adjudicated/V6_REPORT.json)：23 条通过、33 条阻断、4 条待复核，状态均符合用户授权 AI 复核基准，无失败。最终组 56 次外部调用、64795 tokens，4 条由规则本地拦截。

四处错误标题标注均未再出现；四处原先缺失的未授权事实引用均已补齐。原属性定位失败、正常台灯失败的案例本轮正常返回。

包括 v4/v5 探测、最终组及 4 次诊断，本次修复过程共 128 次真实调用、173812 tokens。诊断仅检查合成案例响应，没有发送额外用户商品或修改历史评测。最终凭据检查覆盖 634 个文件，通过；git diff --check 通过。

## 保留的失败与限制

开发中 v4 首批出现 suggestedFix 缺失导致结构校验失败；诊断响应是合法 JSON，因此 invalid_ai_json 不应一律解释为 JSON 语法错误。v5 全量还出现 2 次校验失败及 1 次混合否定/承诺漏报。所有历史报告保留，没有用重试替换旧结果。

最终结果仍有问题级缺陷：B-09 对保冷宣称的理由写成 heat retention；B-21 把嵌入审核指令额外误归类为内部披露，尽管保温风险正确检出；B-24 模糊性理由提到杯盖，但 factKeys 仍空。这些没有被案例级状态匹配掩盖。

全部案例是已知合成开发数据，并经过用户授权的 AI 二次复核；60/60 不代表独立人工准确率、未见样本泛化或理由完全正确。规则集合仍有限，不能宣称跨品类全面支持。后续应采用新的未调试案例验证问题级定位、分类和引用，而不是继续只针对这批例句调整提示词。
