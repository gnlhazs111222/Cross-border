## 已交付

- 独立 `QwenReviewProvider`：输入服务端事实和完整文案，允许合理改写，返回问题位置、原句、事实引用、类别和修改建议。
- 四类问题：规格冲突、无依据宣称、未授权事实、内部信息泄露。已有事实白名单继续生效，暂不宣称支持任意品类。
- 本地硬规则先于网络：识别到内部商业信息/凭据或现有绝对防漏风险时直接阻断。内部原句在问题列表中隐藏；云端不接收被识别的泄露正文。
- Qwen JSON 结构、状态一致性、原句位置及事实引用经过服务端验证；失败不回退成规则通过。模型的建议只是展示，不自动执行。
- 服务端审核持久化：running / passed / blocked / needs_human_review / failed；增量 migration 只给 ReviewResult 添加 metadata。
- 新审核开始先失效旧审核和发布；请求在 SQLite 事务外执行；保存前检查文案/事实/任务上下文、审核尝试和失效状态。
- 同一文案并发审核被拒绝，进程重启遗留 running 最长 180 秒后可重试；使用 SQLite 单机 Demo 的并发边界，不宣称分布式任务队列。
- 查询、刷新、发布和 CSV 读取不调用模型。发布要求当前有效审核；模型、Prompt、规则、事实、任务、文案或模式不匹配时不能沿用批准。
- UI 显示配置模式、实际调用与本地阻断区别、失败与人工复核状态、引用位置及审核追踪；保持旧规则/离线流程。
- 48 个冻结合成案例、指标模块、CLI 评测器和逐样例报告；新增 `npm run eval:review`。

## 重要边界

1. **这里的独立评测指单独的数据、标签和运行器，不是独立人工认证。** 48 条案例与预期答案由 AI 编写，未经过业务同学人工复核；dev/holdout 可在仓库中看到，也包含同类风险的近似表述。
2. 审核根据已有已确认事实判断一致性，不能鉴定原始证据真假。当前 PDF/图片仍含 Mock；原稿生成成功、usedFacts 或审核通过都不是产品真实性证明。
3. 真实开发评测发现隐含防漏漏报，见下表。需要人工复核和扩大真实匿名案例后，才能判断适用性。
4. 当前消费者字段仍受 COPY_FACTS 白名单限制。台灯功率等扩展字段未进入授权输入，因此跨品类/新增性能正例可能误报。泛化探测案例用于展示缺口。
5. 内部信息识别是有限本地规则，不能承诺完整 DLP；常见采购、申报、运费、利润和凭据表达已测。不会因为一项公开规格数值碰巧等于采购价格就把它自动认定为泄露。
6. 高风险、歧义、失败或运行中的审核都不授予发布资格。模拟发布不代表真实上架或全面平台合规。

## 如何启动与使用（Windows PowerShell）

先在原服务终端 Ctrl+C。当前环境 Node22 位于临时目录，执行：

```powershell
cd E:\hks\Create_new_products
$env:PATH = "$env:TEMP\prismlaunch-runtime\node-v22.14.0-win-x64;$env:PATH"
npm.cmd exec prisma generate
npm.cmd run dev
```

`npm run dev` 自动迁移并保留已有数据，随后启动前端5173和后端3001。若临时运行时被清理，改用正常安装的 Node22.12+。Windows 下用 `npm.cmd` 避免 PowerShell 的 npm.ps1 执行策略问题。

默认 `REVIEW_PROVIDER=rules`，不会因为已经开启 Qwen 文案生成而自动改为语义审核。

要启用 B，在本机 `.env` 设置并重启：

```dotenv
REVIEW_PROVIDER=qwen
REVIEW_MAX_TOKENS=1800
AI_LIVE_ENABLED=true
```

沿用已有服务端 `BAILIAN_API_KEY` 与 `BAILIAN_TEXT_MODEL`，不要向前端或聊天发送密钥。全局模型调用预算与零自动重试继续有效，审核、推荐和生成共享运行进程的预算。

登录 → 选择商品并确认事实 → 生成文案 → 审核与发布 → 运行审核。页面配置提示应为“规则 + Qwen”，实际结果还会说明模型是否被调用。

建议按以下流程演示：

1. 保持事实不变，把容量句式合理改写后重审；规则模式通常触发 R002，语义模式可以判断等义改写。
2. 把 500ml 改为 750ml，重审并查看容量冲突的位置与依据。模型有残余不确定性，不能保证每次均正确。
3. 到文案工作室修正，重新审核；只有当前有效结果通过才允许模拟发布。
4. 模型失败显示审核失败及安全错误码，点击运行审核重试；不会悄悄回退通过。

本轮不新增 AI 自动改稿。原安全模板修订 API 保留；语义问题按建议手动编辑再审核。

## 评测命令

不调用真实模型的完整规则基线：

```powershell
npm.cmd run eval:review -- --provider rule --split all
```

显式真实模型小样本（有调用费用）：

```powershell
npm.cmd run eval:review -- --provider qwen --split dev --limit 4 --live
```

必须显式 `--live` 和 `--limit`，每次最多12例；没有自动重试，输出存到新的时间戳目录，不覆盖历史。真实模式需要后端配置中的 Live 和 Key；测试环境强制关闭 Live。没有全量48例的真实 Qwen 效果结论。

标签与 rationale 不发送给模型。报告逐例保存结果、来源、延迟、调用 Token、脱敏错误码、输入哈希和同例规则结果。细节见 [评测说明](../evaluation/review/README.md)。
