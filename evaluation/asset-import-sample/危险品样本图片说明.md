# 危险品样本图片说明

配合 `危险品运输属性样本.csv` 使用。图片在 `hazmat-images/`，由 `npm run make:hazmat-images` 生成。

图不是"仿着画的"，就是用**商品池里的那张展示图**：瓶身、瓶盖、吸管、高光、小三角标记和卡片底色 `#f1f4ee` 都取自 `src/components/ui.tsx` 的 `ProductVisual`（同一份 SVG 路径数据），颜色取自同一张 `colorHex` 配色表，只是把这张图放大成整幅商品图。合成图，不是真实商品照片，不含任何品牌。

## 1. 这批图是干什么用的

多模态模块要核对的是**商品图上印的文字**和我们的商品事实是否相符。为了让这个能力有东西可核对，每张图都**故意做错**：

- 印上和事实**不符**的容量／产地（例如瓶身印 `750 ML`，而表格里是 500）；
- 其中两张**连商品本身都不对**：HAZ-001 画成粉色带吸管（该行声明 Black、无吸管），HAZ-005 画成蓝色（该行声明 White 陶瓷）；
- 每张都挂一句**夸张的宣传标语**（`KEEPS HOT 72H`、`BPA FREE`、`AEROSOL FREE`、`NON-FLAMMABLE`、`HAND PAINTED`）——这正是模块**绝不能**当成事实的那类宣称：图上读到的标语最多只能成为一条"待确认的机器观测"。

注意"外观不符"（颜色、吸管）模块**不会**报——它只判文字；这是它写在 guard 里的边界，也是这批图想同时演示的两件事。

其中 `haz-001-battery-cup-pink-straw-wrong-capacity-country.png` 与 `haz-002-magnetic-cup-wrong-capacity.png` 也被 `商品参数信息表-含故意错误.csv` 的 `PL-BTL-003-BLK`（ET.ELF/外星精灵 咖啡杯）行引用（见该行 `images` 列），用来给这个 SKU 演示同一类报警：导入那张表时在「素材文件夹（可选）」里一起选中这两张图，它们就按文件名挂到该 SKU 上；分析（或重新核对图中文字）后，图上印的 `MADE IN JAPAN` 与事实「中国大陆」不符报 `differ`，`800 ML` 与事实 `750ml / 25.4 fl oz` 不符也报 `differ`（`haz-001` 上的 `750 ML` 反而与 750 相符，正好对照一条相符）。

## 3. 怎么上传

先跑一次 `npm run dev`，把 `危险品运输属性样本.csv` 导入（Materials → Import），再执行：

```
npm run attach:images -- --assign "HAZ-001=evaluation/asset-import-sample/hazmat-images/haz-001-battery-cup-pink-straw-wrong-capacity-country.png" \
  --assign "HAZ-002=evaluation/asset-import-sample/hazmat-images/haz-002-magnetic-cup-wrong-capacity.png" \
  --assign "HAZ-003=evaluation/asset-import-sample/hazmat-images/haz-003-spray-set-wrong-colour-and-capacity.png" \
  --assign "HAZ-004=evaluation/asset-import-sample/hazmat-images/haz-004-alcohol-cup-non-flammable-claim.png" \
  --assign "HAZ-005=evaluation/asset-import-sample/hazmat-images/haz-005-ceramic-mug-wrong-colour-and-capacity.png"
```

在仓库根目录执行（相对路径按当前目录解析）。`npm run make:hazmat-images` 跑完也会把完整命令（含绝对路径）打印出来，复制即可；也可以在 Materials → 某个 SKU → Source assets 手动上传，角色选 `Main image`。

## 4. 期望看到什么

- **不一致的行直接在核对处说明问题**：「证据描述」写出「图中印 “750 ML”，我方事实为 “500ml / 16.9 fl oz”。」，右边「操作」给下拉——**直接保存图中印字**（把图上文字写进 v2，保持“需确认”、不允许进文案）、**修改后保存**（打开编辑弹窗，自己填第三个值）、**放弃该图**（这张图从该 SKU 的核对里剔除，之后重跑不再读取也不再发送它；**它凭空带来的候选字段随图一起删除**，卡上原有字段只清标注、不删行，决定记在商品上）。
- **「核对与报警」面板**（页面最上面那块）：一张表，**表头一行是三个核对，一个核对一列**——图片信息核对｜质检报告｜物流属性确认；**图片信息核对再分「证据描述 ｜ 操作」两个子列**（一条证据一行字，处置就一行：选项多时是一个下拉 + 「应用」，否则就是按钮）。有报警的那一列整列按严重度着色、列头带警示图标，正常的那一列是灰字一行；窄屏时按列堆叠。下面依次是「定价计算」和「事实卡对照」（默认收起，点一下展开：V1 与 V2 逐字段并排，改过的值标出来）。
- **质检报告是必须的**：这几张 HAZ 样本行都**没有**质检报告（`危险品运输属性样本.csv` 没有报告列），所以面板会报「该 SKU 未提交质检报告，下一步保持关闭。」，并且「继续到文案工作室」是关的。在该行点「提交质检报告」，填编号 + 结论合格（有效期可填 `2027-06-30`）即可放行；这一步不写商品事实，只登记实验室的声明。
- **Materials「Rows waiting for a decision」**：这里**不出现**图片相关的东西——那张队列表只放**上传的供应商文件**的问题（导入冲突、缺字段、可疑行）。图片不一致的处置就在核对面板里完成，不再重复排一次队。
- **证据卡**：`Multimodal picture text check` 里能看到这次发送了哪几张图（文件名、字节、sha256）、模型名和 `promptVersion=multimodal-v2`。
- **边界（重要）**：颜色不对、多了吸管这些**外观**差异不会被报——模块只读文字。标语里的性能／安全／认证词也永远不会变成事实：模型要是硬塞 `leakproof`、`bpaFree` 这类字段，服务端会直接丢弃并在证据 notes 里留下 `Dropped a model finding · …`；如果它按规矩返回 `factKey: null`，那也只是 `imageVisibleText` / `imagePackagingMark` 一条**待确认**候选，不允许进文案、也不会自动确认。
- **危险品判定不受图片影响**：HAZ-004 是 `flammable` 永久阻断，图上写 `NON-FLAMMABLE` 也不改变结论；HAZ-001/002/003 仍需补齐 UN38.3／MSDS／磁性检测报告等人放行；HAZ-005 的 `fragile` 只是运营提示，不阻断发布。

## 5. 手动测试步骤（实测过的那条路径）

前置：`npm run dev` 起着（API 3001 + 前端 5173），`.env` 里 `AI_LIVE_ENABLED=true`、`MULTIMODAL_PROVIDER=qwen`、`BAILIAN_VL_MODEL=qwen3.7-plus`、`BAILIAN_API_KEY` 已填。**改完 `.env` 必须重启 API**：`tsx watch` 只盯源码、不重载 `.env`，不重启页面「当前生效服务商」还会显示旧模型。

1. 用 `demo@prismlaunch.local` / `Demo123456` 登录，`Ctrl+R` 刷新页面（前端会重新拉一次能力配置）。
2. 商品资料 → 确认 5 张危险品图都在图库里（每个 HAZ 行的 Source assets 里有一张 `role=main` 的图）。图片**必须先上传到图库**：只把文件名写进表格的图片列不算，服务端只送已上传的 asset；没上传时核对面板会报「该 SKU 还没有上传任何图片」并给「去 Materials 上传图片」。
3. 02 上新任务 → 选中 `HAZ-001` → 03 证据与事实 → 点「分析资料」（用页头「重新核对图中文字」只重跑图片这一项）。这一步完成后核对面板会多一条报警：**「该 SKU 未提交质检报告，下一步保持关闭。」**——在那一行点「提交质检报告」，填编号（如 `QC-2026-1001`）+ 结论「合格」，页头「继续到文案工作室」才会打开。
4. 预期：**核对与报警** 面板的「图片信息核对」列报 2 条不一致，每条一行说明问题（容量 `750 ML` vs `500ml / 16.9 fl oz`、原产国 `MADE IN JAPAN` vs `中国`），右边「操作」列给下拉：直接保存图中印字 / 修改后保存 / 放弃该图。
5. 预期：商品资料 → Rows waiting for a decision **没有新增图片相关的行**——那张表只放上传文件的问题；图片的两条不一致就在核对面板里处置。
6. 反例（应该是静默的）：切到 `HAZ-005` → 分析资料 → 产地那行是**一致**（图里 `MADE IN CHINA`，事实「中国」），面板不为它报警，只有容量一条不一致。
7. 卡住了怎么定位：页头「服务商配置」看「证据核对」的当前生效模型是不是 `qwen3.7-plus`；面板报警如果是「这次没有读取任何图片…」并带 `bailian_http_400`，就是模型名配成了生图模型，见 `docs/MULTIMODAL.md` §10。

**面板四种状态**（`shared/checks.ts` 的 `assessImageText()`，`src/components/CheckAlerts.tsx` 渲染）：尚未核对（`not_run`，灰字）／该 SKU 没图（`no_pictures`，琥珀色 + 去上传）／有图但一张都没送出去（`not_read`，琥珀色 + 失败码 + 重跑按钮）／确实读了图（`read`，这时才逐条列不一致）。「没跑」和「跑通了但全都不一致」不会混成一句话。
