# 质检报告样本说明

配合 `质检报告样本.csv` 使用，用来验证「核对与报警」面板里的**质检报告核对**：正常的静默，异常的报警。

## 1. 数据从哪来

质检报告走**供应商文件的可选列**，和运输属性（`liquid`/`battery`/…）同一套做法：

| 列名 | 含义 |
| --- | --- |
| `reportNo` | 报告编号。**留空 = 该 SKU 没有报告**（安静，不报警） |
| `reportResult` | `pass` / `fail`（也接受 `合格`/`不合格`、`通过`/`不通过`） |
| `reportValidUntil` | 有效期，必须是 `YYYY-MM-DD` |
| `reportCapacityMl` | 报告**自己写的**容量，用来和我们的事实比 |
| `reportMaterial` | 报告**自己写的**材质 |

关键点：`report*` 这几列是**报告的说法**，不是我们的说法。它们和 `capacityMl`、`material` 是两套数据，所以"报告与事实不一致"才看得出来。列格式不对（例如有效期写成 `2026/08/31`）整行会被判为无效行并给出原因，而不是被半读进去。

## 2. 每行对应的预期结果

| SKU | 报告 | 预期 | 说明 |
| --- | --- | --- | --- |
| `QA-001` | `QC-2026-1001`，pass，2028-06-30，500 / Stainless Steel | **静默** | 面板只显示一行灰字：报告已登记、有效期内、与事实一致 |
| `QA-002` | `QC-2025-0311`，pass，**2026-08-31** | **报警（已过期）** | 阻断发布；可「放弃该报告」，或补一份覆盖当前批次的报告后重新导入 |
| `QA-003` | `QC-2026-2205`，**fail** | **报警（结论不合格）** | 永久阻断发布，**不能放弃**；只能修正数据或下架 |
| `QA-004` | `QC-2026-3301`，pass，报告写 500，行里是 **750** | **报警（容量不一致）** | 直接说出问题：`报告写的是 "500 ml"，我方事实为 "750 ml"` |
| `QA-005` | 无（`reportNo` 留空） | **静默** | 未登记报告属于资料缺口，不是异常；和"未申报运输属性"一样安静 |
| `QA-006` | `QC-2026-4402`，pass，报告写 **Ceramic**，行里是 Stainless Steel | **报警（材质不一致）** | 同 QA-004 的处置方式 |

## 3. 手动测试步骤

1. `npm run dev`，打开 http://localhost:5173 （服务端模式）。
2. Materials → Import：选 `质检报告样本.csv`，模式 `Append`，导入。
3. 在候选池里选中 `QA-001`，创建/沿用上新任务，进入 **03 Evidence & Facts**，点 **Analyze Evidence**（会自动跑一次图片文字核对）。
4. 看 **Fact Review 上方新增的「核对与报警」面板**：
   - `QA-001`：`质检报告` 一行是灰字「报告 QC-2026-1001：已登记，有效期至 2028-06-30，与商品事实一致。」，徽标是绿色的 `无异常`。
   - 换成 `QA-002`：琥珀色报警「报告 QC-2025-0311 已于 2026-08-31 过期。」+ 按钮「放弃该报告」。
   - `QA-003`：红色报警「报告 QC-2026-2205 结论不合格。」且**没有**任何放弃按钮。
   - `QA-004`：红色报警 + 逐条问题行 + 「采纳报告值」/「放弃该报告」。
   - `QA-005`：灰字「该 SKU 未登记质检报告，暂无可核对内容。」
5. 点「采纳报告值」后回到表格：`Capacity` 变成报告的取值、状态是「需确认」、来源徽标变成「Manual Confirmation」；报警随之消失（事实已经和报告一致）。
6. 点「放弃该报告」后刷新页面：面板仍是安静状态，决定记录在商品数据 `checkDecisions` 里（谁、什么时候、放弃了哪份证据），之后每次重跑核对都不会再拿它报警。
7. 发布阻断：`QA-003`（不合格）走到发布时始终是阻断；`QA-002`、`QA-004` 在处置之前也是阻断，处置之后放行。

## 4. 图片文字核对的三个处置（同一套「核对处」逻辑）

商品图上的印字和事实不一致时，Fact Review 表格的「Picture text check」列会**直接写出问题**，并给出三个选项：

| 动作 | 行为 |
| --- | --- |
| **直接保存** | 采纳图中印字：写进 v2（保持"需确认"、不允许进文案），并把该条核对的判定改成 `与事实一致`，报警消失 |
| **修改后保存** | 打开编辑框（框里同时显示图中印字），人工改写后保存；改动后的取值如果和图中印字一致，报警消失，否则该条仍保持"不一致" |
| **放弃该图** | 这张图不再参与核对：它贡献的判定全部撤掉，待裁决行按"已跳过"关闭，并且决定记录在商品上，之后重跑核对**也不会再读这张图** |

三个动作都只改 v2，**V1 永远保持供应商交付时的原样**；每一步都要人点，模块自己不会替人做决定。想复现图片不一致，见 `危险品样本图片说明.md`（那批图就是故意印错字做出来的）。
